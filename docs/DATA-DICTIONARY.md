# 轨检数据定义

- CSV 表头 `event_id,run,kind,at,odo_mm,ref,grade`。ID、车次、基点和缺陷类别都是字符串。`kind` 为 `anchor` 或 `defect`。时间须带偏移，转换为 UTC。测距与标称里程以整数毫米记录，`grade` 为 1–3。空字符串与哨兵均隔离，空文件、全空白、仅表头分别报错。来源行号按 CSV 记录起行计。
- 列名支持固定字段重排。相同 `event_id` 若规范化后字段均相同则只计一次，冲突时该组全部隔离。先以文件顺序判断各车次 900 秒迟到窗口，再按 UTC 排序。空白行单列原因，重复表头单独记段。
- 测绘表列出 `ref`、`chain`、`station_mm` 与计划半开区间。匹配按车次与测绘基点取最高等级。最高等级内位置或时间冲突则留缺，完全相同取最早文件行。
- 换表记录为 `ticket,run,at,before_mm,after_mm`，随提交体 `meters` 数组给出（`/api/*` 的 POST，以及批次归档）。`at` 须带偏移并归到 UTC，同一车次同一时标只允许一条，读数取 0–10^12 的整数，否则整份请求报 `BAD_METER`。`before_mm` 是旧表在换表瞬间的读数，`after_mm` 是新表起读。
- 时间与测距都以左闭右开分配相邻标定点；缺右端、超过 120 秒、不同链或两端测距不递增时不复位。区间中测距倒走的事件单独隔离。标称里程按端点进行线性插值，半毫米按 HALF_UP 取整。下行标称里程可以递减。
- 区间内含换表记录时一律按记录裁定（端点读数涨跌都一样，两只表不能直接比大小）：记录落在两侧基点之间（左开右闭，与断链分配同侧）且能把「左基点读数 → 换前读数」与「换后读数 → 右基点读数」两段都接上的，按 `换表接续` 复位，距离按两段之和计算；接不上就整段按 `METER_UNVERIFIED` 留缺。没有换表记录的下降按 `ODO_REVERSAL` 倒走处理。断链与掉线优先于换表，换表记录只作旁证。换表记录序号从 1 起，与报文行号分开记。
- 接续区段内的报文按自身时标选用换表前或换表后的表（换表瞬间及之后用新表），读数须落在当前表的活动范围内，且换算后的测距不得倒走；不满足的单条隔离。复位里程按接续后的总距离对两端标称里程插值。
- 缺陷按链号、类别、位置排序，距离群起点最多 5000 mm 才并入，保留全部报文编号及行号。不同链的相同标称数值彼此独立。含换表接续报文的群保留换表单号与换表记录行号。
- 覆盖按链把计划区间和有效区间各自求并集，再求交。接续区段照常计入已映射，`spliced_mm` 只统计落在计划内的部分。重复覆盖是裁剪到计划后的原始长度与已映射长度之差。缺证片段带相交断档原因或 `NO_COVERAGE`，落在缺证里的换表记录单列 `meter_gaps`。输入报文数等于采信、隔离和重复之和。
- 归档键为输入、测绘表、换表记录、参数和规则版本的 SHA-256。带统一 UTC 创建时间和耗时的快照在一次事务存入；写锁冲突整体回滚后重试一次。签发摘要为固定 JSON 序列化后的 SHA-256，可复算文件完整性。
- 上传限制 2 MiB。UTF-8 BOM、UTF-8 与 GB18030 文件按顺序解码。测绘表与换表样例随部署发布。归档无外部电子证书服务。
